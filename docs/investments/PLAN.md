- **נתוני שוק:** פס כותרת (S&P 500, ביטקוין, פחד וחמדנות) שמושך מ-CNN/Yahoo/Binance ישירות מהדפדפן, עם גיבוי דרך פרוקסי CORS ציבוריים. אין מפתחות API ואין צד שרת.

## 2. ארכיטקטורה מוצעת

### מעטפת וניווט
- מתג ראשי בכותרת: **מחשבונים | השקעות**, באותו מיקום ובאותו גודל לוגו. אזור המחשבונים הקיים נשאר כפי שהוא (אותו DOM, אותם מזהים) ורק מוסתר/מוצג.
- אזור ההשקעות: לשוניות **לוג · פילוח · ביצועים · תנועות** (ובהמשך **גרפים / לוחות**), באותה מסגרת, אותם כפתורים, טפסים, מצבי ריק/טעינה/שגיאה, עם אקסנט משלו.
- בשונה מהמחשבונים, טבלאות ההשקעות צריכות גלילה פנימית (טבלה עם כותרת דביקה וגלילה אופקית במסך קטן). הגלילה תהיה בתוך אזור התוכן, כך שהמעטפת לא קופצת.

### שכבות נתונים (מופרדות)
1. **נתוני מקור** — מה שהמשתמש הזין או ייבא: פעולות (קנייה, מכירה, הפקדה, משיכה, דיבידנד, עמלה, ריבית, מס, המרת מט"ח, פיצול, יתרת/אחזקת פתיחה), נכסים (סימול, בורסה, מטבע, סוג, סקטור), תוכניות מסחר, הגדרות (עמלת ברירת מחדל, מטבע בסיס).
2. **נתוני שוק** — מחירים היסטוריים ושערי המרה, עם מקור וזמן עדכון. מטמון נפרד, ניתן למחיקה ולבנייה מחדש.
3. **נתונים מחושבים** — אחזקות, מנות (lots), עלות, רווח ממומש/לא ממומש, מזומן, סדרות שווי יומיות. **לא נשמרים כמקור**; מחושבים מחדש מהמקור (עם memo לביצועים).
4. **הגדרות תצוגה** — גרפים שמורים, לוחות בקרה, סינונים.

### מנוע חישוב משותף
- קובץ מנוע טהור (בלי DOM) שמשמש את הטבלאות, הכרטיסים, הגרפים והייצוא, ונבדק ישירות ב-Node.
- **דיוק כספי:** סכומים נשמרים כמספרים שלמים ביחידת המטבע הקטנה (אגורות/סנטים); כמויות בסקאלה של 10⁻⁸ (מספיק גם לקריפטו). עיגול רק בתצוגה ובייצוא, בכלל אחד.
- **כל פעולת קנייה/מכירה מייצרת את תנועת המזומן שלה** בתוך המנוע. תנועות ידניות הן רק הפקדות/משיכות/תנועות חיצוניות — כך אין ספירה כפולה.
- **עמלה** נשמרת על הפעולה עצמה (סכום + מטבע). ברירת המחדל רק ממלאת את הטופס; שינוי שלה לא נוגע בהיסטוריה. בקנייה העמלה נכנסת לעלות, במכירה מקטינה את התמורה — פעם אחת בלבד.
- **תשואה:** הפקדה ומשיכה אינן רווח/הפסד. תשואה לתקופה בשיטת Time‑Weighted (שרשור תשואות יומיות סביב תזרימים), ובנוסף רווח כספי = שווי סוף − שווי התחלה − הפקדות נטו. שיטת עלות (ממוצעת / FIFO) תיקבע לפי האקסל.

### שמירה
- שלב ראשון: `localStorage` במפתח עצמאי `anav.portfolio.v1` עם `schemaVersion` ומיגרציות, גיבוי/שחזור JSON וייצוא XLSX — בדיוק כמו המחשבונים היום. מעבר ל-IndexedDB אם הנפח יגדל (מחירים היסטוריים).
- סנכרון בין מכשירים / כמה משתמשים — **החלטה פתוחה** (דורשת שרת ומסד נתונים, ואולי עלות).

### נתוני שוק
- ממשק ספק אחיד (`getQuotes`, `getHistory`, `getFx`) כך שאפשר להחליף ספק בלי לגעת במנוע התיק.
- מפתח API סודי לא יכול לשבת באתר סטטי. נדרשת פונקציית שרת קטנה (למשל Cloudflare Worker / Netlify Function) לפי מקום האירוח — **החלטה פתוחה**.
- בחירת הספק תיעשה רק אחרי בדיקה בתיעוד הרשמי (כיסוי בורסות — במיוחד ת"א אם נדרש, השהיה/סוף יום, עומק היסטוריה, התאמות לפיצולים ודיבידנדים, מגבלות, מחיר ותנאי הצגה). לא מניחים זמן אמת חינמי.
- מטמון, איחוד בקשות כפולות, סימון "מחיר מיושן", והצגת מקור וזמן עדכון בכל מקום שמוצג מחיר.

## 4. החלטות פתוחות וסיכונים

- **האקסל חסר** — אין לנעול עמודות, סוגי פעולות ושיטת עלות לפניו.
- **אירוח וצד שרת** — לא ידוע איפה האתר מתארח. בלי צד שרת אין מפתחות API מוסתרים ואין סנכרון.
- **פרוקסי CORS ציבוריים** בפס הכותרת הקיים אינם בסיס אמין לנתוני תיק; לא נשתמש בהם למחירי אחזקות.
- **פריסת מסך קבוע** — טבלאות ארוכות דורשות גלילה פנימית; צריך לשמור שהמחשבונים לא ישתנו.
- **IIFE יחיד** — מודולי ההשקעות יתווספו בסוף ה-manifest ויחשפו רק ממשק צר, כדי לא לפגוע בסדר ההרצה הקיים.
